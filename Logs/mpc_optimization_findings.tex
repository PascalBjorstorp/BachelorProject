\section{Task B: CPU MPC Optimization}

The CPU MPC targets the Jetson Xavier NX (ARM Cortex-A57 @ \SI{1.9}{\giga\hertz}), tested on an x86 laptop.

\subsection{Float32 Conversion}
\label{sec:float32}
The original CPU implementation used Q16.16 fixed-point arithmetic (matching the FPGA). This was converted to native \texttt{float32} operations:

\begin{itemize}
  \item \textbf{fp\_math.h}: \texttt{typedef float fixed\_point\_t}. All \texttt{fp\_*} functions became inline float operations (\texttt{fp\_mul(a,b) = a*b}).
  \item \textbf{fp\_math.c}: Reduced to ~130 lines (matrix-vector ops only). Removed Taylor series and Newton-Raphson approximations.
  \item \textbf{riccati\_solver.c}: Complete rewrite. All \texttt{int64\_t} intermediates $\to$ float. Removed all \texttt{>> FP\_FRAC\_BITS} shift operations. \texttt{invert\_2x2} uses \texttt{1.0f/det}.
  \item \textbf{mpc\_riccati.c}: Fixed bitshift on float (\texttt{>> 1} $\to$ \texttt{* 0.5f}).
\end{itemize}

\subsection{Algorithmic Optimizations (from FPGA)}
Several FPGA-originated optimizations were ported to the CPU:
\begin{itemize}
  \item \textbf{Warm-start fix}: Removed \texttt{!prev\_converged} condition, increased kappa threshold from 0.3 to 0.5.
  \item \textbf{Adaptive rho every 2 iterations}: Checks ADMM primal/dual balance every 2 iterations instead of every iteration, reducing overhead.
\end{itemize}

These reduced average iterations from 14.2 to 13.1 per solve and improved tracking (max lateral error from \SI{0.836}{\meter} to \SI{0.742}{\meter}).

\section{Task A: FPGA MPC Optimization}

The FPGA targets the Ultra96-V2 (Xilinx ZU3EG) at \SI{100}{\mega\hertz} using Q16.16 fixed-point arithmetic.

\subsection{Algorithmic Optimizations}
Six optimizations were applied to reduce iteration count:

\begin{enumerate}
  \item \textbf{B-matrix sparsity}: Exploiting the sparse structure of the Frenet linearized model's B matrix to skip zero multiplications.
  \item \textbf{Persistent rho}: Maintaining ADMM penalty parameter $\rho$ across solver calls instead of resetting (warm-starting the dual).
  \item \textbf{Max iterations 50$\to$30}: Reduced maximum ADMM iterations with negligible accuracy impact.
  \item \textbf{Adaptive rho every 2 iterations}: Reduced adaptive rho check frequency (halves computational overhead of the check).
  \item \textbf{Newton-Raphson reciprocal 6$\to$4 iterations}: Reduced NR iterations for Q16.16 division.
  \item \textbf{Warm-start fix}: Same as CPU (kappa threshold 0.5, removed prev\_converged check).
\end{enumerate}

\section{Task C: Simulator Accuracy}

\subsection{Dynamics Model Alignment}
The simulation testbench was rewritten to match the f1tenth\_gym's single-track (ST) dynamic model exactly:

\begin{itemize}
  \item \textbf{Model}: 7-state single-track $[X, Y, \delta, V, \psi, \dot{\psi}, \beta]$
  \item \textbf{Integrator}: RK4 (4th-order Runge-Kutta), matching gym's integrator.py
  \item \textbf{Steering}: Bang-bang PID controller (\texttt{pid\_steer}) converting desired angle to steering velocity at $\pm\dot{\delta}_{\max}$
  \item \textbf{Kinematic/Dynamic switch}: At $V < \SI{0.5}{\meter\per\second}$, uses kinematic bicycle; above, uses full tire-force dynamics
  \item \textbf{MPC\_SIM\_MATCHING}: Enabled in vehicle\_model.c to align MPC's internal prediction model with the simplified gym tire model (linear slip angles, no $\cos(\delta)/\sin(\delta)$ force resolution)
\end{itemize}

\subsection{Raceline Fix}
The optimization-generated raceline (\texttt{traj\_race\_cl.csv}) had a $\pi/2$ heading offset from the map coordinate frame. This caused the car to barely move in simulation (reaching only \SI{2.29}{\meter\per\second} before waypoint matching failed). The fix was to add $\pi/2$ to all $\psi$ values in the CSV, verified by computing $\text{atan2}(y_{i+1}-y_i, x_{i+1}-x_i)$ for all waypoints and confirming a constant offset with $\sigma = 0.015\,\text{rad}$.

\subsection{Gym Bridge Improvements}
\begin{itemize}
  \item \textbf{Control model}: Changed from kinematic (\texttt{'ks'}) to single-track (\texttt{'st'}) dynamics
  \item \textbf{Control input}: Changed from \texttt{['speed', 'steering\_angle']} to \texttt{['accl', 'steering\_angle']} --- the MPC outputs acceleration, not speed
  \item \textbf{Parameter overrides}: Added \texttt{v\_switch} and \texttt{v\_min} as configurable parameters in sim.yaml
  \item \textbf{Starting pose}: Updated to match raceline[0] position ($x=0.190$, $y=-0.752$, $\psi=-2.888$)
  \item \textbf{All measured vehicle parameters}: Already properly overridden via sim.yaml
\end{itemize}

\subsection{Key Accuracy Insight}
The gym bridge interprets \texttt{drive.speed} from AckermannDriveStamped messages as \textbf{direct acceleration} (m/s\textsuperscript{2}), not as a speed setpoint. This is correct for the MPC controller which outputs acceleration commands. However, any controller publishing speed setpoints will behave incorrectly with the \texttt{'accl'} control input mode.

\section{FPGA B-Matrix Bug Fix}
\label{sec:bmatrix_bugfix}

A sparsity exploitation bug was discovered and fixed in \texttt{riccati\_solver\_hls.c} at three locations in the Riccati backward pass:

\begin{enumerate}
  \item \textbf{Step~1 (M-computation):} B-matrix rows~2--5 were being skipped --- only row~5 for column~0 and row~2 for column~1 were used, due to hardcoded single-row indexing.
  \item \textbf{Step~2 (S-computation):} The Schur complement calculation had the same single-row issue.
  \item \textbf{Step~6 ($B^\top p$ feedforward):} The $p$-vector update likewise used only one row per column.
\end{enumerate}

All three sites were replaced with proper loops over rows~2--5, ensuring that every non-zero entry of the B~matrix participates in the backward pass.

\textbf{Impact:} Correctness fix. Result: 6/6~PASS, no change in average iterations (solver already converged due to dominant $Q$~diagonal), but the computed gains are now mathematically correct.

\section{FPGA Accuracy \& Resource Optimizations}
\label{sec:fpga_accuracy}

Two changes targeting FPGA synthesis quality:

\subsection{Over-Relaxation Simplification}
The ADMM over-relaxation step was algebraically simplified:
\[
  \hat{x} = \alpha x + (1-\alpha)z
  \;\;\longrightarrow\;\;
  \hat{x} = x + (\alpha - 1)(x - z)
\]
The original form requires two multiplications per element; the new form requires one.
Across all state and control variables this saves \textbf{208~DSP multiply operations per ADMM iteration}.
Result: identical convergence (3.8~avg iterations), better FPGA resource utilization.

\subsection{Deferred P~Normalization}
In the Riccati backward pass, ten accumulation sites were changed from per-multiply normalization (\texttt{>> FP\_FRAC\_BITS} after each product) to accumulation in \texttt{int64\_t} with a single shift at the end.

\textbf{Overflow analysis:} Worst case is 8~terms $\times$ max Q16.16 value $\approx 2^{42}$, safely within the \texttt{int64\_t} range of $2^{63}$.

\textbf{Result:} Marginal accuracy improvement (heading error $-0.5\%$), no convergence change.

\section{Wall Constraint Tuning}
\label{sec:wall_constraints}

Systematic investigation of wall constraints for the ADMM solver.

\subsection{Problem}
Real wall distances (minimum \SI{0.05}{\meter} in tight sections) caused the solver to struggle: 23--30~average iterations, wall collisions, and only 23\% of simulation time above \SI{5}{\meter\per\second}.

\subsection{Solution}
Three complementary changes:
\begin{enumerate}
  \item \textbf{Enforce minimum wall distance of \SI{1.2}{\meter}} in the trajectory via \texttt{--min-distance} in \texttt{compute\_wall\_distances.py}.
  \item \textbf{Reduce MPC wall margin} from \SI{0.25}{\meter} to \SI{0.05}{\meter} (the safety margin now comes from trajectory pre-processing).
  \item \textbf{Add \texttt{WALL\_CONSTRAINT\_END} parameter} --- only constrain the first~5 of 20~horizon steps (near-term safety, far-horizon freedom).
\end{enumerate}

\subsection{Binary Search}
A sweep over minimum distance values: \SI{0.3}{\meter}--\SI{1.0}{\meter} $\to$ FAIL; \SI{1.2}{\meter}$+$ $\to$ PASS.

\textbf{Result:} CPU 6/6~PASS (10.9~avg iterations with walls), FPGA 6/6~PASS (3.8~avg iterations with walls).

\subsection{Soft Wall Constraints}
\label{sec:soft_walls}
The hard box constraints in the ADMM z-update were replaced with a \textbf{proximal operator} formulation:
\[
  \text{prox}_{g/\rho}(v) =
  \begin{cases}
    \dfrac{k \cdot \text{bound} + \rho \cdot v}{k + \rho} & \text{if } v \text{ violates bound,} \\[4pt]
    v & \text{otherwise.}
  \end{cases}
\]
Hard constraints caused ADMM divergence at tight walls because the discontinuous gradient at the boundary prevented smooth convergence. With soft constraints ($k = 500$), the minimum wall distance can be reduced from \SI{1.2}{\meter} to \SI{0.5}{\meter}.

\textbf{Key insights:}
\begin{itemize}
  \item On Spielberg, walls rarely bind --- the raceline naturally stays within bounds.
  \item Previous failures at \SI{1.0}{\meter} were due to the unoptimized solver (no rho persistence), not wall distance.
  \item Soft constraints provide a smooth penalty gradient that guides the solver away from walls rather than hitting an infeasible wall.
\end{itemize}

\section{Universal Raceline Pipeline}
\label{sec:raceline_pipeline}

A new script \texttt{optimize\_trajectory.py} provides one-command trajectory generation:

\begin{lstlisting}[language=bash]
python3 optimize_trajectory.py --map path/to/map.yaml
\end{lstlisting}

\noindent\textbf{Pipeline stages:}
\[
  \text{Map (PGM)} \;\to\; \text{Boundary extraction} \;\to\; \text{Centerline (periodic B-spline)} \;\to\; \text{Width (ray-cast)} \;\to\; \text{TUM min-curvature optimizer} \;\to\; \text{MPC CSV}
\]

\noindent Key features:
\begin{itemize}
  \item Works on both designed maps (Spielberg) and SLAM maps (\texttt{my\_track\_map}).
  \item Auto-scales centerline point count based on perimeter: $n_{\text{pts}} = \lfloor\text{perimeter} / 0.4\rfloor$.
  \item Curvature-based width capping ($w \leq 0.8\,R$) prevents TUM optimizer spline normal crossings.
  \item Heading convention: $\psi_{\text{TUM}} + \pi/2 = \psi_{\text{MPC}}$.
\end{itemize}

\section{Nonlinear Simulator Model}
\label{sec:nonlinear_sim}

The simulation testbench (\texttt{test\_sim\_drive.c}) was updated to match \texttt{f1tenth\_gym}'s \texttt{single\_track.py} exactly, replacing the previous CommonRoad linear approximation.

\subsection{Changes}
\begin{itemize}
  \item \textbf{Slip angles}: \texttt{atan2}-based computation (nonlinear) instead of small-angle linear approximation.
  \item \textbf{Force resolution}: $\cos(\delta)/\sin(\delta)$ terms for front tire forces (full body dynamics).
  \item \textbf{Load transfer}: Explicit longitudinal load transfer model.
  \item \textbf{Tire saturation}: Nonlinear tire forces with proper saturation in tight corners.
\end{itemize}

\subsection{Comparison}
\begin{table}[H]

\label{tab:sim_model}

\midrule

Force model   & Small-angle simplification & Full $\cos/\sin$ resolution \\

\textbf{Result:} 6/6~PASS with similar tracking quality. The nonlinear model provides physically accurate tire saturation in tight corners, matching the simulator the MPC will actually run against.

\section{Summary of Key Findings}

\begin{enumerate}
  \item \textbf{Float32 conversion} provides a 43\% speed improvement on CPU with no accuracy loss, and enables compiler autovectorization (\texttt{-O3 -ffast-math}) for a total 65\% reduction.
  \item \textbf{200\,Hz is the optimal control rate} --- higher frequencies provide no tracking improvement (but 400\,Hz helps with tolerance relaxation).
  \item \textbf{Raceline heading convention} must be verified when importing from external optimizers --- a $\pi/2$ offset caused complete simulation failure.
  \item \textbf{Plant-model matching} (enabling MPC\_SIM\_MATCHING) is critical for the ST dynamic model to avoid tire model discrepancies between the MPC predictor and the gym simulator.
  \item \textbf{Persist adapted $\rho$} provides a 72\% CPU solve time reduction ($11.0 \to 3.2$ avg iterations).
  \item \textbf{B-matrix sparsity fix} corrects all 3~locations in the FPGA backward pass.
  \item \textbf{Soft wall constraints} ($k=500$ proximal operator) replace hard box constraints, reducing minimum wall distance from \SI{1.2}{\meter} to \SI{0.5}{\meter} without ADMM divergence.
  \item \textbf{Universal raceline pipeline} supports any map $\to$ optimized trajectory in one command.
  \item \textbf{Over-relaxation simplification} saves 208~DSP multiplies per FPGA ADMM iteration.
  \item \textbf{Weight tuning bug fix \& 1850-combo sweep}: $Q_{\text{hdg}}=300$, $Q_{\text{vel}}=30$ give 24\% velocity error reduction and 9\% more time above \SI{5}{\meter\per\second}.
  \item \textbf{FPGA tolerance relaxation} ($0.1 \to 0.5$): 56\% iteration reduction ($5.6 \to 2.5$), estimated \SI{279}{\micro\second} per solve.
  \item \textbf{CPU tolerance relaxation} ($0.1 \to 0.5$): 50\% solve time reduction to \SI{8.7}{\micro\second} at 200\,Hz; \SI{6.2}{\micro\second} at 400\,Hz.
  \item \textbf{Nonlinear simulator model}: \texttt{atan2}-based slip angles, full $\cos/\sin$ force resolution matching \texttt{f1tenth\_gym}.
\end{enumerate}
